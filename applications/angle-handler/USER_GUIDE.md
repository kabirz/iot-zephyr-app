# 手柄用户使用手册

摇杆操控器：采集摇杆角度和按键状态，通过 CAN 或 nRF24L01+ 2.4G 无线发送给无线接收器/上位机；同时接收扫描仪回传的超欠挖、激光测距、坐标数据并显示在 OLED 屏上。

---

## 1. 硬件与默认配置

| 项目 | 默认值 |
|------|--------|
| MCU | STM32F103RC @ 72 MHz |
| 显示 | SH1106 OLED 128×64 (I2C) |
| 无线 | nRF24L01+ (SPI2), 1 Mbps, 0 dBm, 5 字节地址 |
| CAN | bxCAN, 11-bit ID |
| 摇杆 | 双轴电位计 (ADC1 ch14/15) |
| 默认连接模式 | CAN（可切换为 RF24） |
| nRF24 信道 | `1`（固定，不可配） |
| nRF24 地址 | 由 MCU UID 的 CRC32 派生（每机唯一，见第 6 节） |
| 上报周期 | 800 ms（心跳）；摇杆数据每 20 ms（CAN）/ 60 ms（RF24） |

**按键：**
- **电源键（PA1）**：短按睡眠/唤醒；10 分钟无操作自动睡眠
- **连接切换键（PA10）**：切换 CAN / RF24 模式
- **handler 按键**：状态随帧上报

## 2. 数据帧协议（扫描仪 → 手柄）

扫描仪设备（或经无线接收器下发的上位机数据）需按以下格式发送。多字节整数一律**大端序（Big-Endian）**。

### 2.1 OVERBREAK_LASER（帧ID `0x263`）—— 超欠挖 + 激光测距

8 字节载荷：

```
字节0     字节1     字节2-3         字节4-7
[flags]   [reserved] [overbreak]    [laser_distance]
```

| 字段 | 偏移 | 类型 | 说明 |
|------|------|------|------|
| flags | 0 | uint8 | bit0 = 超欠挖有效，bit1 = 激光有效（1=有效） |
| reserved | 1 | — | 忽略 |
| overbreak | 2-3 | int16 BE | 超欠挖值，**单位：毫米**（显示时 ÷1000 转米） |
| laser_distance | 4-7 | int32 BE | 激光距离，**单位：毫米**（显示时 ÷1000 转米） |

**数值约定**：原始整数即毫米数。例如 `overbreak=1234` 显示为 `1.234 m`，`laser=5678` 显示为 `5.678 m`。超欠挖可为负数（int16 范围 ±32.767 m）。

### 2.2 COORD_XY（帧ID `0x363`）—— X/Y 坐标

8 字节载荷，**无 flags 字节**，收到即视为有效：

```
字节0-3       字节4-7
[coord_x]    [coord_y]
```

| 字段 | 偏移 | 类型 | 说明 |
|------|------|------|------|
| coord_x | 0-3 | int32 BE | X 坐标，单位：毫米（÷1000 转米） |
| coord_y | 4-7 | int32 BE | Y 坐标，单位：毫米（÷1000 转米） |

### 2.3 COORD_Z（帧ID `0x463`）—— Z 坐标

8 字节载荷：

```
字节0-3       字节4     字节5-7
[coord_z]    [flags]   [reserved]
```

| 字段 | 偏移 | 类型 | 说明 |
|------|------|------|------|
| coord_z | 0-3 | int32 BE | Z 坐标，单位：毫米（÷1000 转米） |
| flags | 4 | uint8 | bit0 = Z 有效（同时影响 X/Y 有效性） |

> **注意**：收到 COORD_Z 帧时，Z 的有效标志会**同时覆盖** X/Y 的有效性。

## 3. 数据帧协议（手柄 → 无线接收器/上位机）

手柄主动发送以下帧。

### 3.1 HANDLER_STATE（帧ID `0x1E3`）—— 摇杆状态（周期上报）

8 字节载荷：

```
字节0-1       字节2-3       字节4     字节5-7
[x_angle]    [y_angle]     [button]  [0xFF 0xFF 0xFF]
```

| 字段 | 偏移 | 类型 | 单位 | 范围 | 说明 |
|------|------|------|------|------|------|
| x_angle | 0-1 | int16 BE | 0.1° | -200~+200 | X 轴角度（-20.0°~+20.0°） |
| y_angle | 2-3 | int16 BE | 0.1° | -200~+200 | Y 轴角度（同上） |
| button | 4 | uint8 | — | 0/1 | handler 按键状态 |
| 填充 | 5-7 | — | — | 固定 0xFF | 占位 |

**解析示例（Python）：**
```python
import struct
x_raw, y_raw, button = struct.unpack('>hhB', payload[:5])
x_deg = x_raw / 10.0    # 原始值 ÷10 得到实际角度
y_deg = y_raw / 10.0
```

**上报频率**：CAN 模式每 20 ms，RF24 模式每 60 ms；按键状态变化时立即上报（10 ms 去抖）。

### 3.2 COBID_HEATBEAT（帧ID `0x763`）—— 心跳

1 字节载荷，值固定 `0x05`。周期 800 ms（仅连接建立且唤醒时发送）。

### 3.3 TEST_FRAME（帧ID `0x777`）—— 测试帧（仅 RF24）

载荷首字节为子命令：

| 子命令 | 值 | 载荷格式 | 用途 |
|--------|----|---------| ------|
| PING | 0x01 | `[0x01][seq]` | 链路测试请求 |
| ECHO | 0x02 | `[0x02][seq][0x00]` | PING 应答 |
| DATA | 0x03 | `[0x03][seq][文本数据...]` | 自定义文本 |

## 4. 显示内容

OLED 128×64 屏幕布局（当前配置：8x16 字体，不显示 XYZ）：

```
┌──────────────────────────────────────┐
│ NRF ▓▓▓              🔋             │  ← Row0: 模式(NRF/CAN) + 信号 + 电池
│                                      │
│ OB:12.345 m                          │  ← Row1: 超欠挖（米）
│ Dis:1.234 m                          │  ← Row2: 激光测距（米）
└──────────────────────────────────────┘
```

- **无效数据显示为 `--------`**（扫描仪未连接或数据无效）
- **信号质量**（仅 RF24 模式）：根据 nRF24 发送重传次数估算，5 档图标
- **电池图标**：根据 ADC 采样电压分档（≥3.85V 满，≥3.75V 高，≥3.55V 中，≥3.40V 低，更低空）

### 数值格式

所有扫描仪数值（OB/DIS/X/Y/Z）显示格式：`整数部分.3位小数 m`，即把毫米值 ÷1000 转米。负数正常显示。

## 5. Shell 命令（串口终端）

### `rf24` —— 无线配置

| 命令 | 说明 |
|------|------|
| `rf24 info` | 显示 nRF24 状态、地址、监听状态（信道固定为 1） |
| `rf24 addr <b0 b1 b2 b3 b4>` | 设置 5 字节地址（立即生效，**不持久化**） |
| `rf24 send <text...>` | 发送 DATA 测试帧 |
| `rf24 ping [count=5] [interval_ms=200]` | RF24 链路 ping 测试 |
| `rf24 listen [on\|off]` | 监听模式（打印收到的 DATA，自动应答 PING） |
| `rf24 diag` | 打印 nRF24 寄存器快照 |

### `link` —— 连接管理

| 命令 | 说明 |
|------|------|
| `link can` | 切换到 CAN 模式（关 RF24，开 CAN 电源，**持久化**） |
| `link rf24` | 切换到 RF24 模式（关 CAN，开 RF24，**持久化**） |
| `link test [count=10]` | 发送 count 个测试帧（通过当前活动链路） |
| `link log [0\|1]` | 开关详细日志（扫描仪数据 + 发送结果） |
| `link rf24_get` | 打印当前地址（信道固定为 1） |

> **切换方式**：除 shell 命令外，也可短按 **PA10 连接切换键** 在 CAN/RF24 间切换。

## 6. nRF24 地址派生（默认地址）

开机时若未从持久化配置加载地址，则按以下算法从 MCU 唯一 ID 派生默认 5 字节地址：

1. 读取 STM32 的 12 字节 UID（`UID_BASE`）
2. 计算 CRC32（多项式 `0xEDB88320`，即反射式，初始 `0xFFFFFFFF`）
3. 地址前 4 字节 = CRC32 的 4 字节（小端序排列）
4. 地址第 5 字节 = 前 4 字节的异或校验

> 每台设备的默认地址不同（绑定 MCU），开机日志可看到 `SN: xxxxxxxxxxxx`。如需与无线接收器配对，需在无线接收器端用 `SET_RF24`（0x14）命令配置相同地址，或在本端用 `rf24 addr` 命令设置无线接收器的地址。

## 7. CAN 远程配置协议

在 CAN 模式下，可通过 CAN 帧远程查询 RF24 配置（信道固定为 1，不可远程修改）：

### RF24_CONFIG_CMD（帧ID `0x110`）

| 子命令 | 载荷 | 说明 |
|--------|------|------|
| `0x02` GET_CONFIG | `[0x02][reserved×7]` | 查询配置，回复 0x111 |

### RF24_CONFIG_RESP（帧ID `0x111`）

```
[cmd 1B][addr 5B][reserved×2]   共 8 字节 (信道固定为 1, 不返回)
```

## 8. 配置持久化

| 存储键 | 内容 |
|--------|------|
| `persist/connect_type` | 连接模式（1=CAN，2=RF24） |
| `persist/rf24_addr` | nRF24 5 字节地址（信道固定为 1，不持久化） |

- `link can` / `link rf24` 命令会持久化连接模式
- shell `rf24 addr` **不持久化**（重启丢失）

## 9. 与无线接收器配合使用

完整数据链路：

```
[手柄摇杆] → 手柄连接板 → CAN 或 [nRF24 → 无线接收器 → UDP] → [上位机]
[显示屏] ← 手柄连接板 ← CAN 或 [nRF24 ← 无线接收器 ← UDP] ← [上位机] ← [扫描仪]
```
```

**配对步骤：**

1. 确认手柄和无线接收器使用**相同的 nRF24 地址**（信道两端均固定为 1）
   - 手柄：`rf24 info` 查看地址；`rf24 addr` 设置地址
   - 无线接收器：UDP 发 `GET_RF24`(0x13) 查询；`SET_RF24`(0x12) 设置
2. 确认两端**加密开关一致**（`CONFIG_NRF24L01P_CRYPT` 都开或都关）
3. 手柄切换到 RF24 模式（`link rf24` 或按 PA10 键）
4. 上位机连接无线接收器的 UDP 端口（数据 9090 / 配置 9200）

## 10. 典型使用场景

### 场景一：扫描仪设备发送数据给手柄

扫描仪（或模拟扫描仪的上位机，经无线接收器转发）发送：

```
帧 0x263: flags=0x03 overbreak=1234(12.345m) laser=5678(5.678m)
  → [02 63] [03 00] [04 D2] [00 00 16 2E]

帧 0x363: x=100000(100.000m) y=-50000(-50.000m)
  → [03 63] [00 01 86 A0] [FF FF 3C 60]

帧 0x463: z=25000(25.000m) flags=0x01(有效)
  → [04 63] [00 00 61 A8] [01 00 00 00]
```

### 场景二：上位机解析摇杆数据（经无线接收器 UDP 收到）

```python
import struct, socket
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.bind(('0.0.0.0', 9091))  # 监听无线接收器数据端口+1
while True:
    data, addr = sock.recvfrom(64)
    frame_id = struct.unpack('>H', data[:2])[0]
    if frame_id == 0x1E3:  # HANDLER_STATE
        x, y, btn = struct.unpack('>hhB', data[2:7])
        print(f"摇杆 X={x/10:.1f}° Y={y/10:.1f}° 按键={btn}")
    elif frame_id == 0x763:  # 心跳
        print("心跳")
```

### 场景三：RF24 链路连通性测试

```
手柄串口: rf24 ping 10           # 发 10 个 ping
手柄串口: rf24 listen on         # 开启监听
无线接收器串口:        rf24 send hello        # 无线接收器发送文本
手柄屏幕日志: RF24 RX: hello     # 收到并打印
```
